# project2# 📊 Проект по обработке витрин данных  

 **Описание проекта**  
Проект состоит из трёх задач, направленных на анализ, очистку и корректировку витрин данных в PostgreSQL.  
Основные шаги включают удаление дублей, восстановление пропущенных данных и исправление несоответствий в расчетах остатков.  

---

## 1. Удаление дублей из витрины `dm.client`  
**Папка:** Задача 2.1  
**Скрипт:** 2-1.sql  

Задача: устранить дубликаты строк, оставив одну уникальную запись для каждой пары:  
- `client_rk` (идентификатор клиента)  
- `effective_from_date` (дата начала действия записи)  

**Основная логика:**  
- Поиск групп дублей через `GROUP BY`.  
- Определение «оригинальной» строки по минимальному `ctid`.  
- Удаление всех остальных дублей.  
- Повторная проверка — в таблице остаются только уникальные записи.  

 **Результат:** витрина очищена от дублей.  

---

## 2. Анализ и восстановление витрины `dm.loan_holiday_info`  
**Папка:** Задача 2.2  
**Скрипт:** 2-2.sql  

Задача: выявить и восстановить отсутствующие записи в витрине, связанной с кредитными каникулами.  

**Основная логика:**  
- Анализ количества строк в витрине и источниках (`rd.deal_info`, `rd.loan_holiday`, `rd.product`).  
- Выявлены пропуски на даты `2023-01-01`, `2023-03-15`, `2023-08-11`.  
- Частичная дозагрузка недостающих данных из временных таблиц `rd.tmp_deal_info` и `rd.tmp_product`.  
- Перегрузка витрины через процедуру `dm.fill_loan_holiday_info()`.  
- Проверка корректности загруженных данных.  

 **Результат:** данные восстановлены, объем витрины соответствует ожидаемому.  

---

## 3. Корректировка данных в `rd.account_balance`  
**Папка:** Задача 2.3  
**Скрипт:** 2-3.sql  

Задача: устранить несоответствия между входящими и исходящими остатками (`account_in_sum`, `account_out_sum`).  

**Основная логика:**  
- Проверка согласованности остатков между днями.  
- Корректировка `account_in_sum` по данным предыдущего дня.  
- Корректировка `account_out_sum` по данным следующего дня.  
- Создание процедуры `dm.fill_account_balance_turnover()` для автоматической загрузки витрины.  
- Валидация данных после обновлений.  

 **Результат:** остатки синхронизированы, витрина формируется корректно.  

---

##  Инфраструктура и запуск  

- Используется **PostgreSQL 15** (порт 5432).  
- Все задачи выполнены SQL-скриптами и процедурами PL/pgSQL.  
- Проект можно развернуть в Docker (docker-compose).
